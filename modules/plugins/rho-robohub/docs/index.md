# The RoboHub platform

An **integration plugin**: everything one ecosystem, RoboHub, needs from the
toolchain, expressed through the toolchain's contracts rather than built into
it. It is the worked example of the {ref}`modules/integrations` contract — read it
when integrating another platform. RoboHub itself is documented separately.

## What it extends

The plugin fills the `platform` contract of four components and the
`module-manifest` contract of the module tools, one hook each:

| Component | Hook | What the platform contributes |
|---|---|---|
| `rho-target` | `spec` | For an STM32 board: the family macro the vendor's driver sources test for, and the vendor's umbrella HAL header |
| `rho-kconfig` | `render` | Nothing yet: the `linux` dialect already writes the header the platform's C includes |
| `rho-cimport` | `map` | Nothing yet: the platform's C headers map as they are |
| `rho-flash` | `flash` | For a board whose flashing tool the platform ships under its own `tools/`, the path to that tool |
| `rho-module` | `contract` | The module types and schemas the platform defines, read from its own contract files in the project's module graph |

It runs only for a project whose module graph names the platform: a module there
declares `platform: robohub`, and the plugin `serves: [robohub]`. A project that
names no platform is built the standard way, with only platform-agnostic plugins.

## What it provides

Its manifest's `integration:` section declares what a project of the platform is
given:

```yaml
integration:
  ecosystem: robohub
  workspace_env: ROBOHUB_WORKSPACE
  provides:
    bindings:
      protocol-bus-c: bindings/c-bus.yml
      protocol-transport-rho: bindings/rho-transport.rho
    ports: ports/
```

| Entry | What it is |
|---|---|
| `workspace_env` | The ecosystem's workspace variable, which a manifest's paths may use alongside `RHO_WORKSPACE` |
| `bindings.protocol-bus-c` | How C generated by `rho protocol generate --platform robohub` reaches the platform's event bus |
| `bindings.protocol-transport-rho` | The wire framing added to generated Rho |
| `ports` | Go ports a project of the platform can ask for by name: `gateway` (serial, UDP, clock and shared state) and `mqtt` (publish to and follow an MQTT broker) |

The toolchain names none of these itself; take the plugin away and they are gone,
which is the point.
